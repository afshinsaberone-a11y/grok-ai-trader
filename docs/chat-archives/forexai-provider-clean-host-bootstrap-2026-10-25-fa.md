## ۶. بازبینی امنیتی اسکریپت نصب با دسترسی Administrator — ۲۵ اکتبر ۲۰۲۶

در بازبینی کد مشخص شد نسخهٔ اولیهٔ اسکریپت نصب، نصب‌کننده‌های Git و Python را زیر %TEMP% قرار می‌داد، در حالی که کل اسکریپت به دسترسی Administrator نیاز دارد. مسیر موقت قابل‌کنترل توسط کاربر کم‌دسترسی می‌تواند هدف سوءاستفاده از junction/reparse point باشد؛ بنابراین این مسیر برای دانلود فایل اجرایی در فرایند elevated مناسب نبود.

اصلاح روی شاخهٔ PR:
- پوشهٔ کاری تازه و نام‌تصادفی زیر CommonApplicationData ایجاد می‌شود؛ مسیر موجود به‌صورت خودکار پذیرفته نمی‌شود.
- پوشهٔ reparse point رد می‌شود.
- ارث‌بری ACL حذف و مجوزها محدود می‌شوند؛ سپس ACL نهایی خوانده و کنترل می‌شود تا تنها SID کاربر elevated و SYSTEM مجوز Full Control داشته باشند.
- پوشهٔ نصب‌کننده بدون -Force ساخته می‌شود.
- اگر فایل نصب‌کننده از قبل وجود داشته باشد، اسکریپت آن را حذف یا بازنویسی نمی‌کند و متوقف می‌شود.

برای این شروط تست قراردادی به tests/test_provider_host_bootstrap_contract.py افزوده شد. آزمون‌های کامل Python و بررسی parser مربوط به PowerShell موفق شدند؛ اعتبارسنجی ایستای G13، Agent Runtime و Project Repair Loop نیز موفق شدند. مسیر آزمون واقعی داده در این CI اجرا نشد.

این شواهد فقط صحت بخشی از قرارداد نرم‌افزار را نشان می‌دهند؛ اسکریپت هنوز روی میزبان واقعی اجرا نشده، PR نیازمند بازبینی است و این تغییر هیچ سرویس، کلید اعتماد یا مجوز معامله‌ای را فعال نمی‌کند. سوابق قبلی این آرشیو و وضعیت‌های باز باقی می‌مانند.


## ۷. محدودکردن مسیر هدف اجرای elevated — ۲۵ اکتبر ۲۰۲۶

در ادامهٔ بازبینی، پارامتر -ProviderRoot بررسی شد. چون اسکریپت با Administrator اجرا می‌شود، مسیر نسبی یا مسیر دلخواه نباید باعث نوشتن فایل‌ها در محلی خارج از محل استقرار موردنظر شود.

نسخهٔ فعلی شاخهٔ PR، مسیر مطلق را اجباری می‌کند، می‌پذیرد که پوشهٔ مقصد فقط فرزند مستقیم CommonApplicationData واقعی ویندوز باشد، والد reparse point را رد می‌کند، مسیر را نرمال می‌کند، پوشهٔ مقصد را بدون -Force می‌سازد و پس از ایجاد نیز ویژگی reparse point را بررسی می‌کند. برای این قرارداد، آزمون متنی اضافه شده است.

این‌ها آزمون‌های کد و CI هستند؛ سرویس Provider، trust anchor، کلید خصوصی یا رجیستری تولیدی پیکربندی نشده‌اند. فقط نسخهٔ بازبینی‌شده پس از موفقیت CI باید بررسی و اجرا شود. در صورت وجود مسیر قبلی یا شکست اعتبارسنجی، وضعیت را بررسی کنید و آن را حذف یا به‌صورت خودکار پذیرفته نکنید.


## ۸. اصلاح تکمیلی منبع ثابت و ACL کلید امضاکننده — ۲۵ اکتبر ۲۰۲۶

در بازبینی تکمیلی، دو مورد با مرز امنیتی مهم پیدا و روی شاخهٔ PR #331 اصلاح شد:

- پارامتر قابل‌تغییر `ExpectedCommit` از اسکریپت elevated حذف شد. اکنون اسکریپت فقط SHA بازبینی‌شدهٔ `41883f30d32747d07d7b7772f8ee7c656a95e4a1` را بررسی‌ و checkout می‌کند. این محدودیت مهم است، چون وابستگی‌ها و تست‌های مخزن با دسترسی Administrator اجرا می‌شوند.
- ابزار تولید کلید، پس از اجرای `icacls`، ACL نهایی را با PowerShell می‌خواند و تنها در صورت غیرفعال بودن inheritance و وجود دقیقاً دو ACE مجاز برای SID کاربر جاری و SYSTEM ادامه می‌دهد. تست جدید وجود ACE اضافهٔ Administrators را شبیه‌سازی می‌کند و باید رد شود.
- نوشتن فایل خصوصی به ایجاد انحصاری با مجوز محدود از همان لحظهٔ ایجاد تغییر کرد تا فاصلهٔ زمانی «نوشتن سپس chmod» وجود نداشته باشد.

Head فعلی: `16923ef4991331ef940ac4637e6e557718f88fdd`.

اعتبارسنجی این SHA: تست‌های Python و PowerShell parser موفق، G13 Workflow Static Validation موفق و Agent Runtime موفق. آزمون real-data عمداً skipped بوده است. جزئیات در [PR #331](https://github.com/afshinsaberone-a11y/grok-ai-trader/pull/331) و کامنت بازبینی آن ثبت شده است.

این تغییرها فقط قرارداد نرم‌افزار و CI را پوشش می‌دهند. هیچ bootstrap واقعی روی VPS انجام نشده، کلید یا trust anchor تولیدی فعال نشده، سرویس/رجیستری تولیدی ساخته نشده و Demo/Live یا ارسال سفارش مجاز نشده است. PR باز و ادغام‌نشده است و هنوز بازبینی مستقل انسانی و برنامهٔ G13 متصل به SHA دقیق main پس از ادغام لازم دارد. تاریخچهٔ قبلی حذف یا بازنویسی نشده است.
